# FlatCFM Project State — 2026-03-17

## Project Overview

Senior thesis implementing flow matching on flat latent spaces for single-cell perturbation modeling. Goal: predict heterogeneous single-cell transcriptional responses to drug perturbations in underrepresented contexts (cell types not seen with specific drugs during training).

The core thesis idea: use a geometrically-regularized autoencoder (PHATE distance preservation) to learn a latent space where the manifold is "flattened" — straight paths in latent space correspond to meaningful biological trajectories. Then run flow matching or neural ODE in this flat latent space to predict perturbation responses.

Advisor: Smita Krishnaswamy. Smita prefers MioFlow-style ODE over flow matching (FM simplifies too much, can't model cell death, etc). FM is used as a baseline. The ODE approach (MioFlow-inspired) uses optimal transport loss + density loss + energy regularization.

Dataset: sci-Plex3 (Srivatsan et al.) via `pertpy.data.sciplex3_raw()` — 188 chemical perturbations across 3 cell lines (K562, A549, MCF-7) at 4 doses (10, 100, 1000, 10000 nM). Raw UMI counts, ~58k genes, median library size ~1500-1700 UMIs per cell (sci-RNA-seq has low depth). ~100k cells subsampled for training.

PerturBench comparison: the perturbench paper evaluates on the same dataset but uses only the highest dose, holds out 30% of perturbations per cell line, and uses 4000 HVG + top 25 DEGs. Their Decoder baseline gets cosine_log_fc=0.35, best model (SAMS-VAE) gets 0.53.

## Data Pipeline Details

### Normalization
- `normalized_log1p`: `log1p(raw_counts / library_size * target_sum)` where `target_sum=10000`
- Library size is computed from ALL ~58k genes (sum of raw counts), not just the selected features
- The selected feature subset (HVG+DEG) is then extracted from the normalized matrix

### Feature Selection: `hvg_union_deg`
- 2000 HVG via scanpy `pp.highly_variable_genes` with `batch_key=cell_type`
- Top 25 DEGs per perturbation per cell type via `scanpy.tl.rank_genes_groups` (t-test with BH correction, control cells as reference)
- Union of HVG + all DEGs → ~6396 unique genes
- DEG computation parameters configurable: `deg_control_column=vehicle`, `deg_control_value=1`, `deg_perturbation_column=product_name`, `deg_cell_type_column=cell_type`, `deg_n_top_genes=25`
- DEGs are computed on `full_dataset` (including held-out cells) — potential data leakage concern since DEG selection sees held-out perturbation responses
- Feature selection is cached: `precomputed_feature_names` avoids recomputation when multiple models share the same space config

### Data Splitting: `underrepresented_context`
- K562 is the test cell type (`test_cell_type: K562`)
- 50% of K562 perturbations held out (`holdout_fraction: 0.5`)
- All A549 and MCF-7 data stays in training
- Held-out K562 perturbations appear in training for other cell types
- Validation: 10% of training cells (stratified by control/perturbed)
- Subsample: 100k cells total (`subsample_n_cells: 100000`, `subsample_seed: 0`)
- AE subsample: 50k cells (`ae_subsample_n_cells: 50000`), stratified by `cell_type × vehicle`

### Pipeline Caching
- Pipelines cached as pickle files at `artifacts/spaces/` keyed by space config tag
- Includes base transform + all projections (including AE model weights if ae_latent)
- Cache key does NOT include AE model weights hash — retraining AE with same tag doesn't invalidate cache
- Fixed: `_ae_projection_is_stale()` checks mtime of AE projection pickle vs pipeline cache
- AE projection pickles saved separately at `artifacts/spaces/sciplex_ae_projection_*.pkl`
- AE model checkpoints saved at `artifacts/models/sciplex_ae_model_*.ckpt`

### Condition Encoding
- Perturbation: `product_name` → categorical embedding
- Perturbation covariates: `dose` → categorical embedding (5 levels including control)
- Sample covariates: `cell_type` → categorical embedding (3 cell types)
- Condition encoder projects all embeddings to 128-dim conditioning vector

## Autoencoder Architecture

### Negative Binomial AE (`NegativeBinomialAutoEncoder`)
- **Encoder**: MLP with LayerNorm + SiLU activations, `n_genes → hidden_dim → ... → latent_dim`
- **Decoder**: separate `decoder_hidden` MLP (latent → hidden) + `dec_log_rate` linear layer (hidden → n_genes)
- **Output**: `mu = library_size * exp(log_rate)` where `log_rate` is clamped to [-20, 20]
- **Dispersion**: `shared_gene` mode — one `log_theta` parameter per gene (nn.Parameter), shared across cells
- **Bias init**: `dec_log_rate.bias` initialized to `-log(n_genes)` so initial mu ≈ library_size / n_genes per gene
- **Alpha**: learnable `nn.Parameter(1.0)` used as scale factor in distance loss

### Reconstruction
- `reconstruct_input(z, lib)` → `log1p(mu / lib * target_sum)` — deterministic decoder mean in normalized space
- `reconstruct_counts(z, lib, sample=False)` → returns mu (NB mean)
- `reconstruct_counts(z, lib, sample=True)` → samples from `NegativeBinomial(theta, mu/(mu+theta))`
- NB sampling produces discrete counts with zeros matching real data sparsity (~87% zeros)
- Decoder mean is smooth/continuous with no zeros — relevant for evaluation (see theoretical limits section)

### Loss Components
- **NBReconLoss**: negative binomial negative log-likelihood, compares raw counts (`x_raw`) against predicted `mu` and `theta`
- **DistancePreservationLoss**: MSE between latent pairwise distances and target (PHATE) pairwise distances, with learned alpha scale, exponential zeta weighting, and per-cell-type masking
- **PullbackIsotropyLoss**: Fisher Information Metric regularization (flatVI-inspired), forces pullback metric G = J^T diag(w) J ≈ alpha * I. Currently weight=0.0 (disabled)
- Loss weights configurable: `recon`, `distance`, `pullback` in `loss.weights`

### PHATE Distance Computation
- PHATE computed on normalized log1p expression using scanpy/phate library
- Config: `n_components=2`, `knn=5`, `n_landmark=2000`, `t=auto`
- `per_cell_type: true` — computes PHATE independently per cell type (each cell type gets its own 2D embedding)
- Embeddings stored per cell, `pdist` computed per batch in dataloader
- Cross-cell-type pairs masked out in loss via `cell_type_ids` tensor
- PHATE embeddings cached as .npy files (separate cache key with `_per_ct` suffix for per-cell-type mode)
- SGD-MDS convergence warnings from PHATE are harmless

### Distance Loss Details (`DistancePreservationLoss`)
Current implementation:
```python
scale = clamp(model.alpha, min=alpha_min)
scaled_targets = scale * original_distances
residuals = (latent_distances - scaled_targets)^2
if zeta > 0:
    weights = exp(-zeta * original_distances)
    residuals = weights * residuals
if cell_type_ids is not None:
    # mask to same-cell-type pairs only
    same_type = cell_type_ids[row] == cell_type_ids[col]
    return mean(residuals[same_type])
return mean(residuals)
```

Parameters (current config):
- `distance_zeta: 20.0` — exponential weighting decay rate
- `distance_alpha_min: 1000.0` — minimum scale factor
- `loss.weights.distance: 0.01` — loss weight relative to recon

**Fundamental issue**: MSE on absolute distances constrains the latent space scale regardless of alpha. The loss can always be trivially minimized by the encoder matching the scaled PHATE structure. Need scale-invariant loss (correlation-based) instead.

### Training Schedules
- **single_phase**: both losses active from start, `task.epochs` total
- **two_phase**: phase 1 (distance only, decoder frozen) → phase 2 (recon only, encoder frozen). 50+50 epochs. Currently NOT used for PHATE AE (switched to single_phase after discovering checkpoint bug).
- Phase transition resets `ModelCheckpoint` state (best_model_score, best_k_models, etc.) and deletes stale phase 1 checkpoint file
- Post-training verification: `_verify_two_phase_checkpoint` warns if saved checkpoint has log_theta=0 (untrained decoder)

### AE Artifact Export
When AE training completes:
1. AE model checkpoint saved to `artifacts/models/sciplex_ae_model_*.ckpt`
2. AE projection (encoder+decoder wrapped in `AELatentProjection`) saved to `artifacts/spaces/sciplex_ae_projection_*.pkl`
3. Metadata JSON with feature names, artifact tags, etc.
4. The projection pickle is what downstream FM/ODE pipelines load

## Key Findings — Detailed

### 1. PHATE Distance-Preserving AE — Latent Space Collapse

**Timeline of investigation**:
1. Initial single-phase training: distance loss drops to 0.0003 by epoch 2, recon stays at 0.385. 1000:1 scale mismatch — distance loss contributes zero gradient.
2. Switched to two-phase: distance converges in phase 1 (0.51→3e-5), recon in phase 2 (0.397→0.368). Looked OK on paper.
3. Discovered checkpoint bug: both best.ckpt and last.ckpt from phase 1 (decoder at initialization, theta=0). Lightning's save_last gated on save_topk — phase 2 never beat phase 1's tiny val_loss.
4. Fixed checkpoint bug, verified theta now trains (range -4 to 3.3, std 1.04).
5. Compared latent variance: PHATE AE total=0.0005, recon AE total=148.1. 300,000x collapse.
6. Investigated: PHATE pairwise distances have median ~0.05. The encoder matches this tiny scale in 128-dim space.
7. Added per-cell-type PHATE + masking: eliminates between-cell-type distances from loss. PHATE computed independently per cell type.
8. Added alpha_min=10: total variance improved to 0.032, but only 1 active dim.
9. Added alpha_min=1000: all 128 dims active, total variance 436. But with weight=1.0, distance overwhelmed recon.
10. Set distance weight=0.01: distance loss collapsed to zero again (1800x smaller than recon by end).
11. FM in this latent space still collapses predictions to single point.

**Key diagnostic plots** (in view_autoencoder_results.ipynb):
- PHATE distance scatter: within-cell-type vs between-cell-type breakdown
- Training target vs latent distances: shows what the loss actually sees
- Latent dimension activity heatmap: variance per dim sorted by magnitude
- Per-gene mean scatter: original vs reconstructed for K562 cells

**Fundamental issue**: MSE distance loss constrains absolute scale. Even with alpha scaling, the *shape* of the latent space mirrors PHATE's compact structure. Need scale-invariant loss.

**Proposed solutions** (not yet implemented):
1. **Correlation loss**: `1 - pearson_correlation(latent_distances, phate_distances)` — completely scale-invariant, only preserves relative ordering
2. **Normalized distance loss**: standardize both distance vectors to unit variance before MSE
3. **Sammon stress**: `sum((latent_dist - phate_dist)^2 / phate_dist)` — weights small distances more

### 2. Checkpoint Bug — Full Details

**Discovery**: Checked model weights in checkpoints. PHATE AE d128 two-phase run (20260315_214033): both best.ckpt and last.ckpt identical (same md5 hash). All decoder weights at Xavier initialization. `dec_log_rate.bias` = -log(6396) = -8.7634 (init value). `log_theta` = 0.0 for all 6396 genes. `alpha` = 1.0 (init).

**Root cause chain**:
1. `ModelCheckpoint(monitor='val_loss', mode='min', save_top_k=1, save_last=True)`
2. Phase 1 val_loss = distance_loss ≈ 0.00003 → saved as best.ckpt
3. Phase 2 val_loss = recon_loss ≈ 0.37 → never beats 0.00003
4. `_save_topk_checkpoint` never triggers in phase 2
5. `_save_last_checkpoint` is gated on `self._last_global_step_saved == trainer.global_step` — only saves when topk also saves
6. Result: both best and last stuck at phase 1 weights

**Fix** (in `AutoencoderPhaseCallback.on_train_epoch_start`):
```python
for cb in trainer.callbacks:
    if isinstance(cb, pl.callbacks.ModelCheckpoint):
        old_path = cb.best_model_path
        cb.best_model_score = None
        cb.best_model_path = ""
        cb.best_k_models.clear()
        cb.kth_best_model_path = ""
        cb.kth_value = None
        cb.current_score = None
        # delete stale phase 1 checkpoint
        if old_path:
            p = Path(old_path)
            if p.exists():
                p.unlink()
                cb.last_model_path = ""
```

### 4. DEG Pseudoreplication Bug (Fixed Earlier)

In DEG Jaccard evaluation: control cells were reused ~21.5x across perturbation groups (568 unique cells in 12,225 rows). This inflated t-test sample size, making the no_effect baseline show DEG Jaccard ~0.43 instead of ~0.

**Fix**: `_unique_rows()` deduplicates control matrix, `_remove_overlapping_rows()` removes control cells that appear in the prediction matrix.

### 5. HVG vs DEG Coverage

Investigation showed 92-96% of perturbation-responsive DEGs are excluded by HVG-only filtering. This motivated the `hvg_union_deg` feature set. Adding DEGs increased gene count from 2000 to 6396 but ensures perturbation-responsive genes are included.

### 6. Sparsity Mismatch in Direct Gene Space FM

Earlier investigation: FM predictions in HVG space had 0% zeros (continuous flow output) vs 97.7% zeros in original data. This fundamental mismatch drives high W1. The NB AE's sampled reconstruction naturally produces sparse outputs matching the data.

## Theoretical Limits

The "theoretical limit" measures AE reconstruction quality: encode ground truth perturbed cells → decode → compare against original. This is the BEST any downstream model in that latent space could achieve.

### How it's computed
For each perturbation group:
1. Encode perturbed cells to latent → decode back to gene space
2. Compute metric (cosine_log_fc, W1, etc.) between reconstruction and original
3. Control cells are original (NOT reconstructed) — this is consistent with how FM predictions are evaluated

### Sampled NB vs Decoder Mean
- **Decoder mean**: deterministic `log1p(mu / lib * target_sum)`, smooth, no zeros. Lower cosine because dense logfc vector doesn't match sparse original structure.
- **Sampled NB**: one NB draw per cell, discrete counts with zeros. Higher cosine because sampling produces realistic sparsity. But single sample adds noise — group mean logfc has variance inversely proportional to group size.
- The FM prediction pipeline uses decoder mean by default (`sample_decode: false`). `sample_decode: true` uses NB sampling.

### Current Theoretical Limits (Recon AE 128d, HVG+DEG 6396 genes)

| Split | Eval Mode | Dose 10 | Dose 100 | Dose 1000 | Dose 10000 |
|-------|-----------|---------|----------|-----------|------------|
| test | sampled_nb cosine | 0.142 | 0.143 | 0.161 | 0.180 |
| test | decoder_mean cosine | 0.076 | 0.067 | 0.070 | 0.061 |
| test | sampled_nb W1 | 0.091 | 0.094 | 0.098 | 0.107 |
| test | decoder_mean W1 | 0.395 | 0.398 | 0.397 | 0.400 |

Higher dose → higher cosine_logfc (stronger perturbation signal relative to reconstruction noise). But even at dose 10000, the limit is 0.18 — well below PerturBench's Decoder baseline of 0.35.

### Why Limits Are Low
1. **50:1 compression**: 6396 genes → 128 latent dims. Perturbation effects are subtle signals lost in compression.
2. **Gene set dilution**: 6396 genes includes many with near-zero logfc, diluting cosine denominator.
3. **NB AE not optimized for perturbation signal**: recon loss treats all genes equally, doesn't prioritize perturbation-responsive genes.
4. Testing larger latent dims (256, 512) to quantify how much compression hurts.

## Known Issues

1. **PHATE AE latent collapse** — unresolved. MSE distance loss constrains absolute scale. Need correlation-based loss.
2. **ODE in PHATE AE produces NaN** — latent space range ±18 too extreme for fixed-step midpoint solver. Need adaptive solver (dopri5) or normalized latent space.
3. **FM overfitting** — train r=1.33 vs held-out r=0.06. Model memorizes perturbation-specific patterns. Need regularization or data augmentation.
4. **AE theoretical limit ceiling** — 0.18 cosine at best dose limits all downstream models. Need larger latent or better AE architecture.
5. **DEG data leakage** — `fit_scope: full_dataset` computes DEGs using held-out perturbation responses. Should use `fit_scope: train` but this caused dimension mismatch issues (fixed with `precomputed_feature_names`).
6. **ODE loss logging** — `train_loss`/`val_loss` arrays empty, only `individual_train_losses.ot` populated. Progress bar shows losses now (fixed isinstance check for tensors).
7. **`_check_library_size_vs_subset` warnings** — cosmetic, fires from `transform_raw()` in notebook evaluation. Not a real issue.
